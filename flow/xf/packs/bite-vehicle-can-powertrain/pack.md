# Pack: bite-vehicle-can-powertrain

Interface `POWERTRAIN` of the first-bite dictionary `vehicle-can`, version 1.0.0, generated by
`tools/bite2pack/bite2pack.py`. Do not edit `pack.def`, `model/vehicle_can.def` or the vectors by hand; change the
dictionary or the generator and run it again.

## Message convention

first-bite identifies a message of this interface by the identifier that arrives with the frame, ANDed with `0x7FF`, not by a payload field.
A message of this pack is therefore 4 bytes of frame identifier (little-endian) followed by the payload.
A payload field `[start, stop)` is `0:<start + 32>:<stop - start>`. The `when` lines read only the bits
the mask keeps; the whole identifier is the key `vehicle_can.powertrain_frame_id`.

`wire bits`, `word_bytes 1`, `bit_order lsb` (the dictionary's `lsb0`). Input and output are hex text.
Every field is `optional`: a payload cut short decodes up to the cut, as in first-bite.

## Scale arithmetic

first-bite rounds `raw * scale + offset` to the decimal places `scale` and `offset` are written with. The engine
computes `raw * num / den`, then `+ offset`. The generator compares the two doubles:

| Transform | Bits | Raw values compared | Doubles that differ | Largest difference |
|---|---|---|---|---|
| `uscale:1/4` | 16 | all 65536 raw values | 0 | 0 |
| `uscale:1:-40` | 8 | all 256 raw values | 0 | 0 |
| `uscale:1/10` | 10 | all 1024 raw values | 0 | 0 |
| `sscale:1/2` | 16 | all 65536 raw values | 0 | 0 |
| `uscale:1/100` | 13 | all 8192 raw values | 0 | 0 |

## What the pack does not state

- first-bite passes a text byte outside 0x20 to 0x7E; the engine refuses the message.
- The dictionary's `port`, `message_length` range, `declared_bits`, `icd_numbering`, `source` and `note` keys have no directive; `port` is how first-bite picks the interface.
